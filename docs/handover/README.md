# 업무 시스템 개발 이관 문서

이 폴더는 이 프레임워크를 가져가 **별도 저장소에서 업무 화면을 개발할 개발자(사람 또는 Claude Code)** 가 이 문서만 읽고 바로 이어서 일할 수 있도록 정리한 것입니다.

- 기준 시점: 2026-10-23, `main` 커밋 `4395f87` (PR #60 외부 API 송신까지 병합). LDAP 모듈(PR #61)은 병합 대기이며 병합되는 내용으로 적었습니다
- 프레임워크 개발은 계속 진행 중입니다. 이 문서는 위 시점 기준이며, 그 뒤의 변경은 맨 아래 "갱신 방법"대로 반영합니다.
- 비밀번호, 서버 주소, DB 계정, 개인 이름 같은 접속·개인 정보는 넣지 않았습니다. 새 저장소에도 넣지 않습니다.

## 방침: 이 프레임워크를 표준 모델로 삼는다

1. 프레임워크를 완성한 뒤(업무 화면 개발 전) **업무 시스템마다 저장소를 따로 만들어** 업무 화면을 개발합니다.
2. 첫 업무 시스템은 **경비대 반출입(통합반출입) 시스템**입니다(기존 Java 시스템 재구축).
3. 그 뒤 다른 업무 시스템도 같은 방식으로 저장소를 하나씩 더 만듭니다. 모든 업무 저장소는 이 프레임워크의 구조·규칙·공통 기능을 그대로 따르고, 프레임워크 자체는 이 저장소(`WebDotNetFramework`)에서만 고칩니다.
4. **전자결재 연동과 AD master 연동(조직 동기화)은 프레임워크 제공 범위 밖입니다**(사용자 결정 2026-10-23). 사이트마다 방식이 달라서 각 업무 저장소에서 업무 개발 때 만듭니다. 프레임워크는 AD 연결용 **LDAP 방식 모듈**만 제공합니다.

## 원본 자료가 있는 곳 (저장소 밖)

업무 분석 자료 원본은 저장소에 넣지 않았습니다. 화면 캡처와 기존 DB 스크립트에 사람 이름, 사업자번호, 메일 주소가 들어 있기 때문입니다. 필요한 내용은 03 문서에 옮겨 적었습니다.

| 자료 | 위치 | 비고 |
| --- | --- | --- |
| 기존 DB 스크립트 (`SCHEMA_infoiv.sql`, `DB_SP_FN_infoiv.sql`, `ADM_COD10/PGM10/PGM20.sql`) | 사용자 PC의 `webframework/docs` 폴더, Claude 프로젝트 공유 폴더 `legacy-db/` | SP 안에 메일 주소 하드코딩이 있음 |
| 업무개발 중요사항 원문 (`업무개발_중요사항.md`) | 같은 곳 | 03 문서 2장에 전문 반영 |
| 기존 화면 캡처 8장 | 공유 폴더 `screens/legacy/` | 사람 이름·사업자번호가 보임 |
| 업무 흐름·화면·규칙 정리 노트 | 공유 폴더 `notes/` (`legacy-business-flow.md`, `legacy-screens.md`, `phase3-business-rules.md`) | 03 문서의 출처 |
| 단계 종료 통합 테스트 확인 목록 | 공유 폴더 `notes/integration-check-list.md` | 프레임워크 쪽 미확인 항목 |
| 업무 전체 설명 | 사용자의 Confluence REFACTORING 페이지 | 클라우드 환경에서는 열 수 없음 |
| 기존 앱 소스 (전자정부 3.8, SQL 매퍼) | **아직 받지 못함** | 미사용 객체 판정과 SP 재작성에 필요 |

## 갱신 방법

프레임워크 개발이 계속되므로 이 폴더도 같이 고칩니다.

1. **언제**: 프레임워크에 기능이 추가·변경되어 업무 개발 방법이 바뀔 때(새 공통 기능, 규칙 변경, 확장 지점 추가), 업무 관련 결정이 새로 나올 때, 업무 저장소를 새로 만들 때.
2. **어디를**:
   - 기능 구현 상태가 바뀌면 [02-framework-status.md](02-framework-status.md)의 표를 고칩니다.
   - 사용법·규칙이 바뀌면 [01-framework-guide.md](01-framework-guide.md)의 해당 절을 고칩니다. 자세한 내용은 원본(`dev-guide.md`, `framework-design.md`)을 먼저 고치고 여기에는 요약과 링크만 둡니다.
   - 업무 결정·미확인 항목이 풀리면 [03-business-gate.md](03-business-gate.md)의 "결정 사항"·"미확인 항목"을 고칩니다(날짜와 결정한 사람의 역할만, 이름은 쓰지 않음).
   - 업무 저장소가 생기면 [04-new-business-repo.md](04-new-business-repo.md)의 "업무 저장소 목록"에 한 줄 추가합니다.
3. **기준 시점 갱신**: 고친 뒤 이 문서 맨 위 "기준 시점"의 날짜와 `main` 커밋을 바꿉니다.
4. **같은 MR에서**: 프레임워크 규칙을 바꾸는 MR은 이 폴더 수정도 함께 담습니다(개발 표준 가이드와 같은 원칙).
5. **업무 저장소 쪽**: 업무 저장소는 프레임워크 업데이트를 가져올 때(04 문서 "업데이트 반영") 이 폴더의 변경 내역도 함께 확인하고, 자기 저장소의 `CLAUDE.md`를 맞춰 고칩니다.
6. **넣지 않을 것**: 비밀번호, 연결 문자열, 서버·내부 주소, 개인 이름·연락처, 캡처 이미지 원본.
